# Claude Design 用デザインブリーフ

以下をそのまま Claude Design に渡す。

```text
社内 PoC 向け「Bedrock API キー発行ポータル」の UI を、全画面・全状態についてデザインし直してください。機能は変えず、見た目・情報設計・操作のわかりやすさを改善するのが目的です。

## プロダクト概要
- 社員（@example.com のメールアドレス）が自分で登録・ログインし、Amazon Bedrock の API キー（長期キー）を 1 人 1 本セルフサービスで発行するポータル
- 発行したキーで Anthropic（Claude）と OpenAI のモデルを us-west-2 で呼び出せる
- 利用者は「一般の参加者」と「管理者」の 2 種類。管理者には上部に「管理」タブが出る
- 言語は日本語のみ。PC とスマホの両方で使う
- トーン: 信頼感があり落ち着いた業務ツール。派手さより「いま何が起きていて、次に何をすればよいか」が一目でわかること。秘密情報を扱うので、注意喚起は目立たせつつ威圧的にしない

## 共通レイアウト
- ヘッダー: ロゴマーク、タイトル「Bedrock API キー発行ポータル」、サブタイトル「PoC 参加者向けセルフサービス」。ログイン後は右側に「APIキー / 管理」タブ（管理者のみ）と「ログアウト」
- フッター: 「このポータルは PoC 用です。メールドメインの確認は在籍の保証ではありません。利用は PoC の利用ルールに従ってください。」
- 通知（アラート）は info / success / warning / error の 4 種類

## 画面 1: ログイン・登録（未ログイン時）
1 枚のカード内で次のモードを切り替える。どのモードにもエラー表示と案内表示がある。
- ログイン: メールアドレス、パスワード、「ログイン」。下に「新規登録」「パスワードを忘れた場合」のリンク。セッション切れで戻ってきた場合は「認証の有効期限が切れました」の警告
- 新規登録: 「登録できるのは @example.com のメールアドレスだけです」の案内、メールアドレス、新しいパスワード（2 回）、パスワード要件の表示（12 文字以上・英大文字・英小文字・数字。不足している要件をリアルタイムに表示）、ドメイン外を入力したら即時にエラー表示し送信不可
- メールアドレスの確認: 入力したメールアドレスをチップで表示、6〜8 桁の確認コード入力（大きめの等幅数字）、「確認してログイン」、「コードを再送（60 秒のカウントダウン付き）」
- 初回パスワード設定: 管理者に招待された人が初期パスワードでログインした直後。新しいパスワード（2 回）と要件表示
- パスワード再設定の依頼: メールアドレス入力、「確認コードを送信」
- パスワード再設定: 確認コード、新しいパスワード（2 回）

## 画面 2: API キー（一般利用者のホーム）
上から順に:
1. 状況に応じたアラート（該当時のみ）
   - 利用対象外のドメイン（error）
   - 管理者により一時停止中（warning。「停止中は推論できず、新しいキーも発行できません」）
   - 新規発行の受付停止中（warning。「発行済みキーの確認・失効は可能」）
2. 「あなたの API キー」カード
   - 状態バッジ: 未発行 / 発行処理中 / 有効 / 一時停止中 / 失効済み / 期限切れ / 発行失敗（色分け）
   - キー情報: マスクされたキー ID（例 ACCA••••••••CDEF、等幅）、発行日時、有効期限（日時 または「無期限」）
   - 有効なとき: 「キー全文はセキュリティのため再表示できません」の説明と「キーを失効する」（危険操作。確認ダイアログあり）
   - 発行できるとき（未発行・失効済み・期限切れ・発行失敗）: チェックリスト（有効期限「発行から N 日間」または「有効期限なし。不要になったら必ず失効」/ キー全文は一度だけ表示 / PoC 目的に限る）、注意文、「API キーを発行」または「API キーを再発行」の主ボタン
   - 発行処理中: 案内と「更新」ボタン
   注意文の全文: 「このキーは Amazon Bedrock の API を利用するためのものです。対応するアプリ/API クライアントで使用してください。Claude Desktop の通常チャットに直接設定することはできません。キーは第三者に共有せず、Git リポジトリにも保存しないでください。」
3. 「今月の利用料」カード: 金額（例 $1.23）、対象月、最終取得日時、注記「AWS Cost Explorer の値（割引・クレジット適用前、UTC の月初から）。反映まで最大 24 時間」。取得できないときは「現在、利用料を取得できません」
4. 「使い方」カード: リージョン、利用できるモデル一覧（「us-west-2 の Anthropic・OpenAI のすべてのモデル（N 件）」として折りたたみ。展開すると等幅のモデル ID がスクロール表示）、環境変数 AWS_BEARER_TOKEN_BEDROCK の説明、curl の動作確認コマンド例（コードブロック、横スクロール）、注意書き（許可外のモデル・リージョンは拒否される／Claude Desktop の通常チャットでは使えない）

## 画面 3: キー発行完了（一度きりの表示）
最重要画面。ここでしかキー全文を見られない。
- 見出し「API キーを発行しました」と強い警告「このキーは今だけ表示されます。ページを閉じると二度と表示できません」
- 暗い背景のキー表示ボックス（等幅・折り返し・全選択しやすい）、「コピー」（押すと「コピーしました」に変化）、「隠す / 表示する」トグル
- コピー後の補足「クリップボードにキーが残っています。貼り付け後は別の文字列をコピーして上書きを推奨」
- リージョン、有効期限（日時 または 無期限）、マスクされたキー ID
- 注意文、「発行直後は反映に数十秒かかることがある」案内
- 「保存しました（キーを閉じる）」ボタン（未コピーなら確認ダイアログ）。ページ離脱時はブラウザの警告

## 画面 4: 管理（管理者のみ）
1. 概要カード群（PC は横並び、狭い画面は 2 列→1 列）
   - 新規発行: 「受付中 / 停止中」を大きく、切替ボタン「発行を停止 / 発行を再開」（確認ダイアログ）
   - 登録枠: 「4 / 10」の大きな数字、使用率メーター、「上限を変更」→ その場で数値入力＋保存/取消（1〜1000。使用数より小さくすると警告）
   - キーの有効期限: 「7 日間」または「無期限」、注記「これから発行するキーに適用」、「有効期限を変更」→ 日数入力＋「無期限」チェック＋保存/取消（無期限を選ぶと漏えいリスクの警告）
   - 今月の利用料: 合計金額、最終取得日時、「再取得」
   - キーの状態: 状態バッジごとの人数一覧（有効・一時停止中・発行処理中・失効済み・期限切れ・発行失敗）
2. 利用者一覧カード
   - 見出し「利用者（N）」、「更新」、メールアドレスでの絞り込み入力
   - 列: メールアドレス、状態（バッジ。保留中なら追加の「停止中」バッジ、発行失敗ならエラーコード）、キー ID（マスク・等幅）、有効期限、登録枠（使用中/—）、今月の利用料（右寄せ）、操作
   - 操作ボタンは状態で出し分け: 有効 →「一時停止」「失効」／一時停止中 →「再開」「失効」／保留中で鍵なし →「再開」／枠を持ちキーが無効 →「枠を解放」。いずれも確認ダイアログ、処理中表示、完了時に success アラート
   - スマホでは表をカード型（ラベル：値の縦並び）に切り替え
   - 注記「状態は登録情報に基づく表示。IAM 側の最新状態は利用者がポータルを開いたときに反映」「利用料は Cost Explorer の値で最大 24 時間遅れ」

## その他の状態
- 読み込み中、API エラー（再読み込みボタン付き）、権限なし（「この操作を行う権限がありません」）
- IP 制限で拒否されたときの 403 ページ（「このネットワークからは利用できません」だけの簡素な静的ページ）

## 実装上の制約（必ず守る）
- React 19 + TypeScript。UI ライブラリは使わず、1 枚の CSS ファイル（CSS 変数でテーマ定義）で実装する
- Content-Security-Policy が厳しい: インラインの style 属性・<style> 要素の動的挿入・外部フォント・外部画像・CDN は使用不可（script/style/font/img はすべて同一オリジン）。必要な見た目はクラスで表現する。進捗表示は <meter> など標準要素を使う
- フォントはシステムの日本語フォント（Hiragino Sans、Noto Sans JP、Yu Gothic UI など）。等幅は ui-monospace 系
- 確認ダイアログは現状 window.confirm。独自モーダルを提案する場合は <dialog> 要素でアクセシブルに
- アクセシビリティ: キーボード操作、フォーカスリング、コントラスト比 AA、状態を色だけで伝えない（バッジに文字）、aria-label の付与
- キー全文は画面以外（URL・ストレージ・ログ）に出さない前提を崩さない
```
